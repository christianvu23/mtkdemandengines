Problem: Worker combines 3 concerns (HTTP routes, Queue handler, Supabase calls) in 316 lines — single responsibility principle violated; any change risks breaking unrelated concerns; worker timeout under concurrent scrape load.

Solution: Split into 3 modules each with one reason to change: api/routes.js (HTTP only), queue/handlers.js (queue processing only), services/supabase.js (Supabase operations only). New Transport interface enables dependency injection.

  • Locality: bugs concentrate in one module
  • Leverage: one interface, N call sites
  • Interface shrinks; implementation absorbs the wrappers
  • Tests hit one interface
  • Delete 4 shallow wrappers

ADR callout: Split worker.js before adding Learner module — otherwise concurrency and timeout risks compound.

Problem: 4 transport adapters embedded directly in transport/index.js with hardcoded fallback chain — adding new transport requires modifying core logic; hard to test adapters in isolation.

Solution: Define Transport interface with lay() method signature. Each adapter (truc_tiep, browser_run, unlocker, nap_tay) implements it. Fallback chain configured via demand_sources table, not hardcoded.

  • Leverage: one interface, N call sites
  • New transports add without modifying core logic
  • Adapters testable with mock implementations
  • Interface shrinks; implementation absorbs the wrappers
  • Locality: fallback config separated from adapter logic

ADR callout: Transport interface enables future transports (e.g. Learner ingestion) without touching core routing.

Solution: Extract LeadIngester interface with single napLead() method. Hand-napping implementation vs auto-napping implementation. Both feed into same demand_inbox via single entry point, preserving conservation law.
